# Prototype Phase Reference

Make ideas tangible quickly so you can learn from them, not admire them.

**Core mantra:** "Build to think, not to ship."

---

## Prototype Selection Matrix

Match what you need to learn to the right prototype type.

| What's Unknown | Prototype Type | Effort |
|---|---|---|
| Does the user want this? | Landing Page / Pitch | Low |
| Does the flow make sense? | Paper Prototype (text) | Low |
| Does the story resonate? | Storyboard | Low |
| Can the user complete the task? | Wizard of Oz | Medium |
| Does the interaction feel right? | Role-Play | Medium |
| Can we build it? | Technical Spike | High |

**Facilitation:**
1. "What's the biggest unknown about your selected idea?"
2. Match to prototype type above
3. "Let's build a quick [type] prototype right now."

---

## Paper Prototype (Structured Text)

Describe screens/states as structured blocks rather than drawings.

**Screen Template:**
```
SCREEN: [Name]
PURPOSE: [What user accomplishes here]
ENTRY: [How user gets here]

LAYOUT:
- Header: [content]
- Primary action: [button/link — label and behavior]
- Content area: [what's displayed]
- Secondary actions: [other options]

ON [action]: → goes to [SCREEN NAME]
```

**Facilitation:**
1. "What's the first screen the user sees? Describe it."
2. Build 4-6 screens covering the core flow
3. "Walk me through the flow: Screen 1 → 2 → ... Does it make sense?"
4. "Where did you have to think hard? That's a usability red flag."

---

## Storyboard Prototype

Visual narrative of the idea in context (6-8 scenes).

**Scene Template:**
```
SCENE [N]: [Title]
Setting: [where, when, context]
Action: [what happens in this moment]
Dialogue: "[what is said, if anything]"
Emotion: [how user feels]
Key Detail: [one thing that makes this scene work]
```

**Facilitation:**
1. "Start with the trigger — what moment pushes the user toward your solution?"
2. Build scenes: trigger → discovery → first use → core value → resolution
3. "Read the whole story aloud. Where does it drag? Where does it sing?"

---

## Wizard of Oz Prototype

Present a "working" interface while manually providing the backend.

**Planning Template:**
```
USER SEES: [the experience as it appears]
BEHIND THE SCENES: [what's actually happening manually]
WHAT WE'RE TESTING: [the specific assumption]
SUCCESS SIGNAL: [how we know it worked]
FAILURE SIGNAL: [how we know it didn't]
```

**Facilitation:**
1. "What part of your idea do users need to believe works?"
2. "Can we simulate that manually while they interact with a simple interface?"
3. Design the user-facing layer and the behind-the-scenes process
4. "What's the cheapest way to make the front feel real?"

---

## Landing Page / Pitch Prototype

Test desirability before building anything.

**Structure:**
```
HEADLINE: [One sentence value proposition]
SUBHEAD: [How it works in one sentence]
3 BENEFITS:
1. [Benefit + brief explanation]
2. [Benefit + brief explanation]
3. [Benefit + brief explanation]
SOCIAL PROOF: [Who else wants/uses this]
CTA: [What action you want them to take]
OBJECTION HANDLER: [Address the top concern]
```

**Facilitation:**
1. "If you had to sell this idea in 10 seconds, what would you say?"
2. Build the pitch structure above
3. "Read this to someone. Do they want to sign up? Why or why not?"

---

## Role-Play Prototype

Act out the service experience as a conversation.

**Setup:**
```
SCENARIO: [The situation]
USER ROLE: [Who the user is, their context]
SERVICE ROLE: [Who/what provides the solution]
TRIGGER: [What starts the interaction]
```

**Facilitation:**
1. "I'll play the [service/product]. You play the user."
2. "Here's the scenario: [setup]. What do you do first?"
3. Improvise the interaction for 5-8 exchanges
4. "Step out of character. What worked? What felt wrong?"
5. "Let's run it again with one change: [adjustment]."
