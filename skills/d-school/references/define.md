# Define Phase Reference

Synthesize empathy findings into actionable problem framings.

---

## Insight Synthesis

Transform observations into insights using the "needs...because" pattern.

**Formula:** [User] needs [need] because [surprising insight].

**Good vs Weak Examples:**

| Quality | Statement | Why |
|---|---|---|
| Strong | "New parents need reassurance they're doing enough because expert advice feels contradictory." | Specific user, emotional need, non-obvious because |
| Weak | "Users need a better app." | No specificity, solution-embedded, no insight |
| Strong | "Freelancers need predictable income visibility because financial anxiety undermines creative risk-taking." | Connects practical need to deeper behavioral impact |
| Weak | "People need to save time." | Generic, no user specificity, no surprise |

**Facilitation:**
1. "From your empathy work, what surprised you most?"
2. "What needs emerged that users didn't explicitly state?"
3. "Let's write 3 insight statements using: [User] needs [need] because [insight]."
4. "Which insight feels most actionable and surprising?"

---

## Point of View (POV) Statement

The bridge between understanding and ideation.

**Format:** [User] is a [descriptor] who needs [need] because/in order to [insight].

**Facilitation:**
1. "Describe your user in a way that captures their relevant characteristics."
2. "What's the core need that, if met, would transform their experience?"
3. "What's the non-obvious reason behind this need?"
4. Assemble and test: "Does this POV make you want to generate ideas? If not, it needs sharpening."

**Quality Check — A good POV:**
- Is narrow enough to be actionable
- Is broad enough to allow creative solutions
- Does NOT embed a specific solution
- Contains a genuine insight (not just a restatement)

## Problem Reframing (6 Lenses)

When stuck or when the problem feels too narrow/broad, reframe it.

| Lens | Method | Prompt |
|---|---|---|
| **Why-Why-Why** | Ask "why" to find higher-order problem | "Why does this problem matter? Why does THAT matter?" |
| **For Whom** | Shift the beneficiary | "What if we solved this for [different user] instead?" |
| **What If Not** | Remove a constraint | "What if [biggest constraint] didn't exist?" |
| **Invert** | Flip the problem | "Instead of reducing [bad thing], how might we increase [good thing]?" |
| **Broaden** | Zoom out | "What larger problem is this a symptom of?" |
| **Narrow** | Zoom in | "What's the single most painful moment within this problem?" |

**Facilitation:**
1. State the current problem framing
2. "Let's reframe through 3 of these lenses. Pick the ones that feel freshest."
3. Generate a new problem statement for each lens
4. "Which reframing opens up the most interesting solution space?"

## User Needs Statements

Distill empathy into structured need declarations.

**Template:**
```
USER: [specific persona or segment]
SITUATION: [context/trigger when need arises]
NEED: [the functional or emotional need]
CURRENT WORKAROUND: [how they cope today]
DESIRED OUTCOME: [what success looks like for them]
```

**Facilitation:**
1. "Who is the primary user and when does this need arise?"
2. "How do they currently deal with this? What's broken about that?"
3. "If we solved this perfectly, what would their experience look like?"

---

## Design Principles

Guardrails for the solution space — what your solution MUST embody.

**Format:** Each principle = verb + value + reason
- "Respect user time by minimizing steps — because cognitive load erodes trust."
- "Default to transparency over polish — because users forgive ugly but not deceptive."

**Facilitation:**
1. "Based on your insights, what 3-5 values must your solution embody?"
2. For each: "Turn it into an actionable principle: [Verb] + [value] + [because]."
3. "If two principles conflict, which wins? That ranking reveals your priorities."

**Test:** A good design principle lets you say "no" to features that violate it.
